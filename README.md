# AdvertApp RU-hunter

Автозабор российских заданий из раздела «Новые заказы» AdvertApp
(`com.advert.mobileearnings.app`) через ADB и Windows OCR. Приложение
не модифицируется: бот только снимает экран, распознаёт карточки и тапает.

## Что нужно

- Телефон подключён по USB, включена отладка по USB (`fab1701`), экран разблокирован.
- AdvertApp залогинен, открыт раздел «Новые заказы».
- Плотность экрана **408** — это настройка пользователя, бот её не меняет
  (проверяет на старте и отказывается при другом значении).
- Windows Python 3.10+ с `pillow` и `numpy`.
- ADB: `C:\Users\RZE\AppData\Local\Android\Sdk\platform-tools\adb.exe`.

## Запуск

Все команды выполняются из корня проекта (`C:\dev\Android_2\advert-hunter`).

```powershell
# Боевой прогон на ближайший час: -30 с перед круглым часом … +6 мин после.
# --dry-run — только навигация и распознавание, без нажатий на карточки/магазин.
python .\hunter2.py --next-hour [--dry-run]

# Несколько часов подряд (по одному прогону на каждый круглый час).
python .\hunter2.py --next-hour --hours 3

# Старт/стоп по времени: HH:MM:SS HH:MM:SS
python .\hunter2.py 17:59:30 18:06:00

# Без аргументов — работает 10 минут с текущего момента.
python .\hunter2.py

# Остановить бот через файл:
python .\hunter2.py --stop
```

Дополнительно: `--refresh-seconds X` — интервал между перезаходами в раздел
«Новые» (минимум 2 с), используется вместо `--next-hour`.

Лог пишется в `logs\hunter2.log` (в режиме одного устройства) или в `runs\<serial>\hunter2.log` (ферма/персональный режим). Результаты (статусы взятия) — в `results.jsonl` (или `runs\<serial>\results.jsonl`), кадры — в `frames\` / `runs\<serial>\frames\`.

## Что происходит

1. В момент старта: `am force-stop` + `am start` AdvertApp (лечит зависший
   splash и оборванный Gsocket). **Данные и аккаунт не трогаются.**
2. Ожидание главного меню (до 110 с, при неудаче — повторный рестарт).
3. OCR находит слово «новые» и тапает по его координатам — сдвиг меню баннером
   не мешает.
4. Каждые ~2–3 с бот перезаходит в «Новые» (новые задания **появляются
   именно при перезаходе**, простой скролл их не подгружает).
5. Каждый кадр: OCR заголовков «Заказ №…». Карточка считается **RU**, если:
   - в её тексте нет «Сменить учетную запись» (иностранный заказ с требованием VPN);
   - это не задание Samsung (Galaxy Store only) — отсечение по эталонной иконке;
   - это не партнёрский заказ («Партнерские заказы», «Telegram бот»);
   - карточка видима полностью и в заголовке есть требование (не обрывок).
   **RuStore и Huawei AppGallery-заказы брать можно.**
6. По RU-карточке: тап → страница заказа → поиск кнопки «Загрузить/Скачать»
   разрешённого магазина (Google Play / RuStore / Huawei AppGallery) → нажатие.
7. Подтверждение забора — **не всегда Play Store**: AdvertApp часто показывает
   окно с данными заказа («взят», «добавлен в активные»). Такое окно бот
   распознаёт, сохраняет в `results.jsonl` как `accepted` и перезаходит для
   обновления списка.
8. Если открылся магазин — бот возвращается назад и продолжает охоту.
   При ошибке/недоступности — запись `unavailable`, заказ блокируется на 90 с.
9. Если RU-карточек нет — бот скроллит вниз (для просмотра нижних карточек)
   и периодически перезаходит.

## Статусы в `results.jsonl`

- `accepted` — заказ подтверждён окном с данными (взят);
- `market_opened` — открылся магазин;
- `unavailable` — заказ уже недоступен/ошибка;
- `samsung` — только Galaxy Store, пропущен;
- `foreign` — «сменить учетную запись»/VPN/смена языка, пропущен;
- `unknown` — ответ на нажатие не подтверждён за отведённое время;
- `mismatch` — на странице другой номер заказа.

## Ограничения

- Телефон должен быть разблокирован и показывать AdvertApp: бот работает
  с реальным экраном, а не с фоновым API.
- Gsocket-соединение приложения иногда рвётся (`java.io.EOFException`) —
  приложение уходит в splash. Бот перезапускает его сам, но момент раздачи
  можно пропустить, если обрыв случится ровно в начале часа.
- OCR — встроенный Windows, только на этом ПК; на Linux/Android понадобится
  другой движок.
- Полный цикл «перезаход → распознавание» ~6 с: два BACK до главного меню,
  затем OCR меню и списка. В час пик пауза между перезаходами 0.5 с.
- Задания разбирают за секунды: в 17:00 оба найденных RU-заказа были уже
  недоступны через 4 с после появления в списке. Бот успевает взять 1–2
  заказа за час, а не все.
- Иностранный заказ определяется по тексту карточки («Сменить учетную
  запись», VPN). Если OCR обрезал строку, страница заказа отсеивается за
  ~1.5 с вместо ожидания 8 с.
- Геометрия рассчитана на экран 1080×2412 (Realme RMX3840, density 408);
  при другом экране потребуется калибровка.

## Архитектура и стратегия (актуальное состояние)

Проект вырос из одиночного «заборщика» в **ферму на два устройства**:

- `farm.py` — супервизор: обнаруживает телефоны по ADB, запускает по воркеру
  `strategy_engine.py --serial <serial> --slot <n>`, перезапускает их после
  каждого прохода (~15 мин). Дедлайн и параллелизм задаются в `panel_settings.json`.
- `strategy_engine.py` — исполнитель планов стратегии. Планы задаются в
  `panel_settings.json → strategy.plans`: `rush` (00:00–08:29) и `day` (08:30–23:59).
  Шаги: `MODAL_PUMP` (модалки всегда), `NAV_TAB`, `SCAN_NEW` (сбор RU),
  `TAKE_NEW` (взять), `EXECUTE_ACTIVE` (выполнить зелёные шаги), `WAIT`.
  `strategy.active = auto` выбирает план по времени суток.
- **Правило «взять ≠ выполнить»**: заказ из «Новых» после установки приложения
  попадает в очередь со статусом `pending`, а не `done`. Он считается
  выполненным, только когда AdvertApp реально показал зелёный шаг
  (`order_confirmed()` / `install_step_confirmed()`). Ложные `instructions_done`
  больше не пишутся.
- **Зелёная подпись = выполнять немедленно**: все actionable-заказы из
  «Активных» обрабатываются в одном проходе пачкой, с пересканом после
  каждого шага. Приоритет — «Найти / Установить / Открыть приложение»
  (у них жёсткий лимит ~40 минут), затем day-gated «Открыть на N день».
- **Магазины**: инструкция определяет магазин из текста (`detect_store()`):
  Google Play / RuStore / Huawei AppGallery / Xiaomi GetApps. Поиск и установка
  идут в нужном магазине, с выбором нужной иконки из модалки; если место
  из инструкции больше видимого списка — заказ пропускается (не ставится
  первое попавшееся приложение).
- **Удаление приложений** (`cleanup`): заказ удаляется только если он появился
  в «Истории» AdvertApp **И** исчез из «Активных», независимо от цвета шагов.
  Перед удалением создаётся бэкап через Swift Backup; если список «Активных»
  прочитан неполностью — удаление пропускается (guard).
- Очередь `runs/<serial>/work_queue.json`: pending старше 2 часов помечается
  `lost` и может быть взят заново (защита от зависших заказов).

## Распознавание (OCR)

Два движка с переключением через `panel_settings.json → ocr.engine`:

- `ocr.ps1` — встроенный Windows OCR (`Windows.Media.Ocr`, ru), исходный путь;
- `ocr_rapid_server.py` — **RapidOCR** с кириллической ONNX-моделью
  (`PPOCRv5 / mobile / cyrillic`), точнее распознаёт цифры (`на 3 день`
  вместо `на З день`) и цены. Работает как сервер по протоколу `ocr.ps1 -Server`.
  Запускается из `.venv-ocr` (не хранится в репозитории — см. зависимости).
  Число потоков на движок ограничено (env `OMP_NUM_THREADS` и параметры
  `intra/inter_op_num_threads`), чтобы не грузить CPU на 100%.

Формат строк OCR сохраняет семантику `words[0]` = цветной маркер шага
(зелёный/жёлтый), `words[1:]` = текст — от этого зависит определение
готовности шагов в `tasks.py` (`step_state`, `step_text_active`).

## Зависимости для запуска

- Python 3.10+ (основной код): `pillow`, `numpy`, `pywinauto` (для панели).
- Для RapidOCR: отдельное окружение с `rapidocr`, `rapidocr_onnxruntime`,
  `onnxruntime`, `opencv-python` (модели скачиваются при первом запуске).
- ADB из Android SDK, телефон с USB-отладкой и разблокированным экраном.

> Репозиторий не содержит логов, кадров, скриншотов и виртуальных окружений —
> они создаются во время работы и исключены через `.gitignore`.
